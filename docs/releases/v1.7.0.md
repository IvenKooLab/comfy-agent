## Changelog

- **Deterministic intent parsing (P0)**: assistant commands now resolve against local enumerable sets first — workflows, characters and styles go through exact → prefix → substring → edit-distance correction (typos like `F1ux` still resolve, names normalized to ignore the "（内置）" suffix). Only a genuine miss falls back to the LLM
- **LLM output schema validation (P0)**: `validate_llm_actions()` enforces an action-key whitelist, converges workflow references to existing local entities, clamps times/seed/count and constrains view enums. Invalid output degrades to a guidance message instead of a raw exception — no more silent format drift
- **@ entity selector (P0)**: typing `@` in the assistant input opens a filterable picker of workflows / characters / styles; the selection becomes a removable chip and the action carries the explicit ID, skipping name guessing entirely. A bound workflow overrides LLM output and the tool loop; a bound character injects its lock string and LoRA node server-side; a bound style feeds prompt enhancement
- **Multi-step action plans with resume (P1)**: `{"actions":[...]}` sequences are persisted to `data/action_plans.json` with a step pointer and per-step results, saved after every step. A failed step does not advance the pointer — the reply shows a "Resume" button that continues from the breakpoint. Also available via `GET /api/agent/plans` and `POST /api/agent/plans/resume`
- **Generation feedback recording (P1)**: gallery delete (rejected) / archive (adopted) / rerun and prompt-enhancement success/failure are logged to `data/feedback.jsonl`, with PNG-embedded generation params (model / sampler / seed / prompt / style) attached automatically. `GET /api/feedback/stats` reports adoption rate, per-model comparison, rerun rate and enhancement failure rate — a measurable "AI suggestion adoption rate" for reporting and self-tuning
- Rules layer now accepts typo-corrected workflow names; "open" supports the Models / Templates pages; built-in help gains 3 assistant Q&A per language
- 22 new regression tests (entity resolution, schema validation, explicit routing, plan checkpoint/resume, feedback stats); full suite 44 tests plus 3 integration scripts green
- **Not done (per user decision)**: loci memory integration — the MCP plumbing exists on both ends, but wiring it in would add configuration and process-lifecycle complexity for now

Full changelog: CHANGELOG.md. Requires local ComfyUI and the WebView2 runtime.

## 更新日志

- **确定性意图解析（P0）**：助手指令先在本机可枚举集合里解析——工作流/角色/风格走精确 → 前缀 → 子串 → 编辑距离纠错（`F1ux` 这类错拼也能收敛，名称归一化忽略「（内置）」后缀）；真正匹配不上才调 LLM
- **LLM 输出 schema 校验（P0）**：`validate_llm_actions()` 强制动作键白名单、workflow 收敛到本机已有实体、times/seed/count 数值域钳制、view 枚举约束；非法输出降级为引导话术而非裸抛异常，杜绝输出格式漂移被静默吞掉
- **@ 实体选择器（P0）**：助手输入框打 `@` 唤起可筛选浮层（工作流/角色/风格），选中生成可删除芯片，动作携带显式 ID 跳过名称猜测；绑定工作流强制压过 LLM 输出与工具循环，绑定角色注入锁定串与 LoRA 节点，绑定风格参与提示词增强
- **多步动作序列断点恢复（P1）**：`{"actions":[...]}` 落盘 `data/action_plans.json`（步骤指针 + 逐步结果，每步落盘），失败步不推进指针；回复带「断点续跑」按钮从断点继续，另有 `/api/agent/plans` 与 `/api/agent/plans/resume`
- **生成反馈记录（P1）**：画廊删除（不采纳）/ 归档（采纳）/ 重跑、提示词增强成功失败全部记入 `data/feedback.jsonl`，PNG 内嵌参数自动关联模型/采样器/seed/提示词/风格；`/api/feedback/stats` 输出采纳率、按模型对比、重跑率、增强失败率——量化风格 SOP 好坏，形成「AI 建议采纳率」汇报口径
- 规则层支持纠错后的工作流名；「打开」新增模型/模板页；帮助页助手模块中英各补 3 条问答
- 新增 22 条回归测试（实体解析 / schema 校验 / 显式路由 / 计划断点续跑 / 反馈统计），全套 44 项 + 3 个集成脚本全绿
- **不做（按用户决定）**：loci 记忆接入——MCP 管道两端现成，但强行加会引入额外配置与进程生命周期复杂度，暂不集成

完整变更：CHANGELOG.md。需要本地 ComfyUI 与 WebView2 运行时。

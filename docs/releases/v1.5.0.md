## Changelog

**🤖 Assistant upgraded to a Function Calling tool loop**

The assistant moved from keyword parsing to a real agent: five built-in tools, the model decides what to call and in which order, up to six rounds before answering.

| Tool | Capability |
|---|---|
| `query_queue` | ComfyUI execution / queue state and VRAM |
| `search_gallery` | Search local gallery results by keyword |
| `read_log` | Read application logs to diagnose errors |
| `launcher` | Query and control ComfyUI (status/start/stop/restart) |
| `submit_generation` | Submit image/video generation (only when the user explicitly asks, count <= 4) |

- Tool calls are shown line by line under the assistant message as `🔧 tool(args) → result`
- When a provider does not support the tools protocol, it falls back to the old intent chain with zero configuration
- Tool results are summarized to keep token usage in check

> This version ships as a source tag; the Windows exe installer will be attached to this release in the next packaging window.

## 更新日志

**🤖 助手接入 Function Calling 工具循环**

助手从「关键词解析」升级为真正的 Agent：5 个内置工具，模型自主决定调用与顺序，最多 6 轮循环后给出结论。

| 工具 | 能力 |
|---|---|
| `query_queue` | 查询 ComfyUI 执行/排队状态、显存 |
| `search_gallery` | 按关键词搜索本地画廊成果 |
| `read_log` | 读取应用日志排查错误 |
| `launcher` | ComfyUI 状态查询与启停（status/start/stop/restart） |
| `submit_generation` | 提交图片/视频生成（仅用户明确要求时，count≤4） |

- 工具调用过程在助手消息下方以 `🔧 工具(参数) → 结果` 逐行展示
- 厂商不支持 tools 协议时自动回落旧意图链路，零配置迁移
- 工具结果摘要化控制 token 体积

> 本版本以源码 tag 发布；Windows exe 安装包将在下一个打包窗口补挂到本 Release。
